# MYN Agent 1.0

## Audit and incremental plan

The existing Next.js App Router application uses React, Supabase SSR authentication, PostgreSQL RLS, OpenAI Responses, transcription/TTS, and a pause-detected hands-free voice loop. Screen images are compressed locally and sent only during authorized questions. Conversations and summaries persist through ownership-scoped RPCs. Elo already has an immersive view and responsive chat. Billing exists and remains untouched.

Reuse those paths. Add a schema-validated task core and durable state/version control; add a separate isolated Playwright worker; connect Guide/Do/Together to one task; share task context with voice/text; add permission, cancellation, verification, recovery and regression tests. A plain screen share never enables desktop control.

Constraints: Vercel functions cannot host persistent Chromium sessions. Execution therefore requires an independently deployed worker and a server-only signing secret. Browser execution is unavailable until configured. Existing provider readiness in this cloud instance does not certify Vercel credentials. Do not fabricate live success. Account/dashboard automation also requires an authorized authenticated browser context; this release starts with fresh public-browser contexts and does not import local cookies or accept passwords.

Security: authenticate every API, scope all records by owner, validate all model outputs, treat page content as untrusted, bound operations/retries, enforce explicit domain grants and per-action approval for navigation/click/fill/select, redact logs and never persist screenshots/passwords. Block private destinations, downloads, popups, browser permissions and arbitrary scripts. Production worker deployment must enforce outbound network isolation as an additional boundary.

## Implemented architecture

- `lib/agent/schema.ts`: validated task modes, plans, primitive actions, observations and assertions. `core.ts`: explicit legal transitions and evidence-based completion. `provider.ts`: injectable planner/decision/visual-verification interface with the existing OpenAI adapter; provider selection is configuration, unsupported providers fail closed. The separate voice model/transcription configuration remains unchanged.
- `server.ts`: ownership-scoped planning, execution leases, exact-action approval, page-fingerprint freshness checks, verification, user controls, retry limits and recovery. No task becomes complete with pending/unverified steps. A repeated unchanged browser observation stops the automatic loop without another model call. The overall request deadline is 45 seconds; worker calls are bounded and limited to 50 actions per task, with at most two failed attempts before user recovery.
- `worker/`: real isolated Playwright adapter with signed short-lived single-use commands, domain checks, private-network denial, per-session ownership, resource/request budgets, cancellation and TTL. Production requires external outbound-network isolation and an HTTPS endpoint. See `worker/README.md`.
- `app/api/tasks`: authenticated task creation/list, task commands, deletion and owner-scoped metrics. Concurrent writes use PostgreSQL row locks and expected versions; pause/cancel/revoke/mode controls invalidate running results. Changing mode retains the objective, plan and verified progress but revokes browser grants/context, requiring a fresh explicit authorization before more execution.
- Migration `0005_agent_core.sql`: seven owner-scoped tables for tasks (steps stored as validated JSON), execution sessions, permissions, tool executions, verification results, events and usage metrics. Normal clients have SELECT only; ownership-checked RPCs perform task mutations. These RPCs allow owners to confirm their own progress; evidence marked `user` is not represented as an independently verified browser result. Existing users, conversations and billing are preserved. The migration was applied to the configured Supabase project.
- `TaskWorkspace` integrates progressive task controls into the existing Elo composer in both normal and immersive views. All new task copy is natural English; existing user-selected interface/conversation languages remain compatible. All three modes share one task, transcript and context. Remaining steps can be edited while paused; completed evidence is preserved. The normal voice/text context now includes the persisted current task.
- Short-term browser observations/screenshots stay ephemeral; durable task objectives, plans, selected mode, permitted domains, results and concise evidence can be reviewed/resumed/deleted. No cross-session preference inference or covert long-term memory was introduced.

## Configuration and material limitations

The repository now contains a real executor, but no publicly reachable worker URL/signing-secret deployment was provided. Do mode must therefore show unavailable until the worker is deployed and `MYN_WORKER_URL`/`MYN_WORKER_SECRET` are securely configured. Do not substitute an ephemeral cloud process URL for a durable production service. No external dashboard changes, purchases, publications or account messages were performed while developing.

The initial worker supports fresh public browser contexts. It does not solve login to Vercel/Supabase, MFA/CAPTCHA or importing the user's desktop cookies. Those priority examples can be guided; automatic authenticated setup requires a dedicated user-controlled remote login flow. Accessible DOM interactions are implemented; visual-coordinate computer control is not. An action's result is checked against the reviewed observable assertion; this is evidence of that result, not proof of every possible business invariant. Screenshots are not retained by default.

Voice continues using the existing STT + Responses + sentence TTS turn-taking. Users can stop playback/voice with the mic control; this is not full-duplex Realtime/WebRTC or acoustic barge-in. Screen images are sent on explicit questions/verification with active sharing, rather than a continuous background stream. Provider credentials/credits and actual live voice/model planning still require successful deployment-side checks; presence of an environment binding alone is not certification.

Metrics log model identity, latency and tokens without prompts/media/secret values. `/api/tasks/metrics` returns owner-only success/verified rates, duration, tool failures, interventions, mode use and resumed-task counts over a bounded sample. Cost remains `null` until actual pricing/cost data is available, rather than inventing a dollar figure. This release supplies no second production model provider or autonomous long-term preference memory.

## Validation

Automated core/API/database checks cover task creation, plans, transitions, mode continuity, invalid schemas/tools, domain/expiry/nonce controls, explicit approvals, stale observations, verification, retry/action limits, cancellation races and owner isolation. PostgreSQL tests use the real migrations. `npm run test:agent-browser` drives actual isolated Chromium against a local sandbox, including form interactions and verified output, missing/disabled targets, private destinations, cross-owner access, signed replay and in-flight interruption.

`scripts/verify-platform.mjs` uses confirmed disposable users on the real configured Supabase project: task ownership, durable transitions, version conflicts, authenticated result confirmation and owner metrics are checked alongside the existing auth/history/RLS paths, then users are deleted. `scripts/verify-conversation-layout.mjs` checks the authenticated task UI, mode switching, explicit user verification and task recovery using real app/database endpoints; **model planning and media responses are explicit test fixtures**, never production fallbacks. Existing public Playwright flows and responsive voice/screen checks remain required. These tests do not certify a hosted worker, paid model readiness or third-party account automation.

Final check results for this increment: **107 unit/API/PostgreSQL checks**, **20 public Playwright checks**, production build and TypeScript passed. The real Chromium worker sandbox passed navigation/form/result checks plus boundary, timeout and cancellation tests. Real Supabase integration and authenticated task-UI mode/verification/recovery checks passed, with temporary users removed. A fresh bounded provider probe in this cloud runtime still returned `AI_AUTH_FAILED`; this does not establish which credential is deployed in Vercel Production. Production planning, voice and automatic browser workflows cannot be certified from these results. The real database migration is applied; the worker endpoint/signing secret still need deployment configuration.
